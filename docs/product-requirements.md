# 产品需求规格

## 1. 文档状态

- 阶段：初版需求确认
- 实现状态：已有最小闭环，完整初版仍在开发
- 目标：定义自托管音乐播放器服务的 MVP 范围、业务规则和验收标准

本文中的“必须”表示初版要求；“预留”表示初版不提供对应界面或完整能力，但实现时不得封死扩展路径。

## 2. 产品目标

创建一个可部署在 Linux 服务器或 NAS 的自托管音乐播放器服务：服务器管理音乐文件和长期数据，手机和电脑通过网页浏览、管理和播放音乐。初期只在本机开发和调试。

初版重点是完成以下闭环：

1. 上传音乐。
2. 自动加入默认歌单。
3. 为歌曲维护歌词和播放参数。
4. 创建、编辑并播放歌单。
5. 在页面意外刷新后恢复播放会话。

## 3. 初版运行边界

- 服务器端和网页客户端均在本机运行。
- 初期开发和本机运行以 Windows x64 为主，但服务器从一开始就必须考虑后续部署到 Linux。
- 后续发布目标至少包括 Windows x64、Linux x64 和 Linux ARM64；业务逻辑不得依赖 Windows 专用路径、进程或文件系统行为。
- 音频由浏览器播放，服务器不负责实时音频输出。
- 初版客户端只有响应式网页，同时面向手机和电脑浏览器；客户端架构必须为未来增加 React Native 原生客户端保留复用空间。
- 初版表面上只有一个默认账号，不显示登录、注册或账号切换界面。
- 服务器持久化歌曲、文件、歌词、歌单和歌曲设置。
- 浏览器本地存储只保存当前浏览器中的播放会话。

## 4. 核心概念

### 4.1 歌曲

歌曲是用户管理和播放的业务对象。歌曲与具体音频文件版本分离，以便替换音频时保留歌曲身份、歌词、设置和歌单引用。

每首歌曲至少具有：

- 稳定且唯一的歌曲 ID
- 所属用户
- 标题及可选的艺术家、专辑、封面等元数据
- 当前可播放的音频版本
- 歌词
- 基础随机权重
- 播放起点和终点
- 单曲音量

### 4.2 歌单

歌单是用户手动维护的歌曲集合，也是随机播放的唯一范围。

- 系统为默认用户自动创建一个默认歌单。
- 上传成功的歌曲自动加入默认歌单。
- 用户可以创建其他歌单，并向其中添加或移除歌曲。
- 一首歌曲可以出现在多个歌单中。
- 初版中，同一首歌曲不能在同一个歌单中重复出现。
- 默认歌单可以重命名，但不能删除。
- 用户可以从默认歌单移除歌曲。
- 如果歌曲还属于其他歌单，从默认歌单移除只移除该歌单关系。
- 如果歌曲只属于默认歌单，从默认歌单移除视为删除歌曲；客户端必须明确说明影响并要求二次确认。
- 删除歌曲后，歌曲进入回收站，并从正常音乐库和所有正常歌单视图中隐藏。

### 4.3 播放会话

播放会话表示某个浏览器标签页当前的播放上下文，包括当前歌单、当前歌曲、播放位置、播放模式和随机衰减状态。

随机衰减状态属于播放会话，不属于歌曲、歌单或服务器端的长期数据。

## 5. 功能需求

### 5.1 音乐上传

- 用户可以上传单个或多个音频文件。
- 系统应尽量接受常见音频格式。初版明确支持 MP3、AAC（裸 ADTS `.aac` 以及 M4A/MP4 容器）、WAV、FLAC、Ogg/Vorbis、Opus、WMA 和 ALAC；FFmpeg 能够解码的其他音频格式可按尽力支持处理。
- 上传过程应显示每个文件的状态，包括上传中、处理中、成功和失败。
- 上传任务入口仅显示正在上传或处理、等待确认的任务数量，不累计会话历史，也不统计内部任务。只展示未完成任务、未关闭的失败及当前页面观察到的成功记录；历史成功不展示。上传中不自动展开面板；全部成功后显示“上传完成”并保留到刷新，停止轮询；失败保留原因，可手动关闭当前页面的提示。刷新后恢复服务器上的未完成任务。
- 系统应读取可获得的标题、艺术家、专辑、封面、时长和编码信息。
- 上传并处理成功后，歌曲自动加入默认歌单。
- 在普通歌单 A 的界面选择文件上传时，新歌曲同时加入 A 和默认歌单；以选择文件时的歌单为准，之后切换界面或重启任务不改变目标。若 A 在完成前已被删除，则只加入默认歌单。默认歌单上传不重复添加关系；同名覆盖仅保留原歌曲归属，不因本次上传入口额外加入歌单。
- 上传先接收文件并读取歌名进行预检查，再进入正式上传列表；预检查期间显示独立的检查进度，不创建可见上传任务或开始转码。以音频标题标签为歌名，没有标签时使用去掉扩展名的文件名；比较时忽略首尾空白及大小写，不比较歌手。同名时先弹窗询问“覆盖 / 取消”，确认后复用已接收文件进入上传任务，不重复传输；取消清理预检查文件并释放配额。预检查文件计入容量，刷新时未确认的预检查需重新选择文件，服务端重启或候选达到一小时后的维护会清理遗留文件。覆盖保留原歌曲身份、歌词、播放设置和歌单关系，成功后立即清理旧音频。激活歌曲时仍进行事务内同名检查，兜底处理并发变化或旧客户端提交，兜底冲突保留原任务内确认流程。回收站和历史重复记录不自动合并，历史多个同名记录优先匹配最早上传的一首。
- 浏览器不能可靠播放的格式应进入转码流程。
- 转码不以无损为目标，优先考虑浏览器兼容性、合理文件体积和处理速度。
- 浏览器优先播放时间轴可靠的原始文件；通过格式能力检测预先选择，不支持或实际解码失败时自动回退到兼容副本，保持当前进度与音量。裸 ADTS AAC 缺少可靠时长与索引，默认使用 MP3 兼容副本；M4A/MP4 中的 AAC 仍可优先原文件。
- 初版统一兼容副本为 MP3：MIME 类型 `audio/mpeg`，LAME VBR 质量等级 `q=2`（通常约 190 kbps），最多双声道，采样率最高 48 kHz。
- 已验证能够直接播放的标准 MP3 文件可以直接作为兼容播放版本，不重复转码；其他格式仍生成上述 MP3 副本以供不兼容设备回退，不代表默认播放转码文件。
- MP3 副本必须含准确的时间索引，转码完成后验证其时长与原文件一致；已有缺少索引的副本通过后台任务无重新编码修复，原文件和歌曲设置保持不变。
- 裸 ADTS AAC 的时长通过完整解码确定，不使用按码率估算的容器时长；历史错误记录自动校准，保留歌词、歌单及歌曲设置，越界播放区间按替换音频的规则调整。
- 原始上传文件应保留，以便将来重新转码。
- 转码失败时保留任务错误信息并清理候选文件；当前可以重新选择文件上传，手动重试转码预留后续实现。
- 用户取消的任务不作为历史上传项展示；候选文件清理完成、配额释放后删除任务记录。清理失败时仅内部保留记录和配额供维护或重启重试，不能先删除记录造成孤立文件；历史遗留的取消记录同样清理。真实上传或转码失败仍保留错误信息。
- 文件完整接收后，任务不依赖网页请求；刷新页面重新获取任务状态，服务重启后重新处理已完整接收的文件。接收尚未完成时刷新会中断上传，需要重新选择文件；初版不支持断点续传。
- 初版不限制单个上传文件大小，也不设置产品层面的上传或转码并发任务数量上限。
- 单个文件仍受剩余总空间限制；空间不足时必须拒绝或中止上传，并给出明确提示。

### 5.2 音乐库管理

- 用户可以浏览音乐库中的全部歌曲。
- 用户可以查看系统从音频文件中读取的歌曲元数据。列表副标题显示歌手和专辑；专辑名与当前歌名相同（忽略首尾空白、大小写及全半角差异）时不重复显示专辑，原始元数据保持不变。
- 用户可以修改歌曲显示名称和歌手；名称去除首尾空白后不得为空，歌手可以清空。修改对所有歌单生效，不改写音频文件或内嵌标签。其他元数据暂不支持手动编辑。
- 歌曲列表可按上传时间或歌曲名正序、逆序显示，默认上传时间逆序；歌曲名采用自然排序（例如歌曲2 在歌曲10 前），使用当前显示名称而非上传文件名，重命名后随最新名称重新排序。显示排序不改变随机播放规则，不提供手动调整顺序。
- 用户可以搜索歌曲；至少支持按标题和艺术家搜索。
- 用户可以删除歌曲。
- 删除歌曲时先进入回收站，不立即移除原始文件、播放副本或相关数据。

### 5.3 回收站

- 删除歌曲后记录删除时间并进入回收站。
- 回收站中的歌曲不参与搜索、正常歌单展示或播放。
- 用户可以查看回收站，并在永久清理前恢复歌曲。
- 恢复歌曲时恢复其删除前的歌单关系；如果关系无法恢复，至少加入默认歌单。
- 歌曲进入回收站满 72 小时后才具备永久清理资格，绝不能提前清理。
- 永久清理采用延迟、尽力执行的方式，挂在方便且可靠的触发点上，例如服务器启动、删除操作、上传完成或低频后台维护任务。
- 因没有触发清理而保留超过 72 小时是允许的。
- 永久清理后才移除原始文件、播放副本、歌词、歌单关系和相关持久化数据。
- 回收站中的文件仍然占用总空间配额。
- 初版不提供“立即永久删除”或“清空回收站”操作，统一由延迟清理机制处理。

### 5.4 替换音频文件

用户可以在歌曲设置中选择替换音频，点击底部“保存”后才上传；选择文件后取消设置不会替换。替换时：

- 保留歌曲 ID。
- 保留歌词。
- 保留所有歌单引用。
- 保留随机基础权重和单曲音量。
- 重新读取时长、格式和音频元数据；保留用户自定义的歌曲名称和歌手，未自定义的字段使用新文件元数据及安全回退值。更新原始文件名，保留歌曲最初上传时间。
- 重新执行兼容性检查和必要的转码。
- 清除或拒绝恢复指向旧音频版本的浏览器播放进度。

替换过程必须先准备并验证新版本，再切换当前音频版本：

- 新版本准备完成前，旧版本继续可用。
- 新版本成功后以原子方式切换。
- 新版本切换成功后立即清理旧音频版本，不设置保留期。
- 如果旧版本文件因占用或文件系统错误未能立即删除，应记录为待重试清理，并尽快释放其占用空间；这不影响新版本继续使用。
- 新版本处理失败时，旧版本不受影响。

原播放区间在替换后按新时长校验：

- 如果原起点不小于新时长，重置为播放完整歌曲。
- 如果起点仍有效但终点超过新时长，将终点调整为新歌曲结尾。

### 5.5 歌词

- 用户可以为歌曲添加、编辑和删除歌词。
- 初版将歌词作为原始文本保存和编辑，也允许用户粘贴或上传 LRC 文本。
- 用户可以使用歌曲元数据或简易文件名解析结果从 LRCLIB 搜索歌词候选。带歌手搜索的可用、去重候选少于 3 个时，补充一次仅歌名搜索；合并去重后仍按原歌手、时长等信息排序，最多显示 8 个候选。
- 在线搜索不得自动覆盖现有歌词；用户选择候选并确认保存后才更新歌曲歌词。
- 候选应展示标题、艺术家、时长以及是否包含同步时间轴，搜索失败不得影响歌曲播放和手工编辑。
- 播放时解析常见的 LRC 行时间戳，高亮并自动滚动到当前行；用户可以点击带时间戳的歌词跳转播放位置。
- 歌曲列表与播放歌词使用独立滚动区域，不将歌词排在长列表底部；宽屏并排显示，窄屏点击顶部歌单进入对应歌曲列表、点击底部播放器的歌曲信息区（封面、歌名、歌手名及其间空白）进入当前歌曲的歌词界面，不提供独立切换组件；返回当前歌单不重置播放，底部播放器始终可操作。歌词自动跟随仅滚动歌词内容，不带动列表或整个页面。
- 为补偿滚动动画，播放时的歌词高亮与滚动默认提前 300 毫秒，与文本中的 offset 叠加；不修改歌词文本，点击歌词仍跳至应用 offset 后的行时间，不减去动画提前量。
- 默认只将同一时间戳的歌词合并成一组，首行为主行，附加行以较小字号显示；整组高亮、滚动和点击跳转，相同文本去重。不按语言或文字种类推断原文和译文。
- 歌曲设置将歌词编辑和显示设置整合在同一面板，以“编辑 / 显示设置”标签切换，共用内容区域并保留未保存内容；显示设置内提供即时预览：用户可选择按原时间戳分组或每行独立显示，并指定组内第一行或最后一行作为主行。独立显示时同时刻的各行一起高亮。显示设置不调整时间，不推断配对关系或提示猜测的歌词格式。
- 不提供单独的偏移设置框。用户直接编辑歌词文本中的 `[offset:毫秒]` 调整整首歌词：正数提前、负数延后，0 为不偏移。编辑内容即时预览，保存歌曲后才影响播放，取消不保存。
- 服务端保存非空歌词时，缺少有效 offset 标签则补 `[offset:0]`；已有有效标签逐字保留，重复保存不重复添加。补标签保留原始 BOM、换行、文字和行时间戳；清空或纯空白歌词不补标签。
- 提前至音频起点之前的行保留原时序，在 0 秒选择最近的一行高亮，点击负时间行时跳到 0 秒。
- 显示设置跟随歌曲保存在服务器，跨歌单、浏览器刷新、服务重启、音频替换及回收站恢复后保持；省略新设置的旧客户端不得清除已有选择。
- 支持可完整对齐的 `[kana:…]` 日文注音标签，读音以小字显示在对应汉字上方，播放和设置预览均显示；沿用歌曲原有时间、双语分组、主行选择和 offset。标签只提供已有读音，不自动生成注音，也不增加逐字高亮。
- kana 对齐包含连续半角或全角数字串，每串占一个槽位。全部正文不能对齐时，分别检查每组第一行和最后一行组成的候选序列；只有一个候选完全对应时，注音绑定到对应文字，不受主行排版选择影响。有多个候选都能对应时，按用户选择的主行 1 / 2 区分；独立行模式下不猜测多解。只接受完整候选序列，或截至最后一个多行组的完整候选序列，未覆盖的末尾单独行保持普通显示。0 秒多行组中，只有一行明确对应唯一的 ti 标题信息时，注音候选使用该标题行，不让同组额外提示占位。不得跳过中间行或根据语言猜测原文。
- 标签格式不支持、内容被删改或仍不能完整对应时保留普通歌词显示；原始文本不改写，kana 标签本身不作为歌词正文展示。
- 普通文本歌词按行展示，不伪造同步时间；初版不支持逐字歌词。
- 歌词跟随歌曲，不跟随歌单。

### 5.6 歌单管理

- 用户可以创建、重命名和删除普通歌单。
- 用户可以向普通歌单添加歌曲、从中移除歌曲；显示时使用上传时间或文件名排序。
- 歌单界面允许勾选单首或全选当前歌单歌曲，使用“添加到”选择其他目标歌单；包含默认歌单在内的目标均可接收歌曲，已存在的歌曲跳过，原歌单关系保留。不再提供“从音乐库添加”折叠列表，来源是当前歌单，不依赖默认歌单是否包含该歌曲。批量添加部分失败时保留失败歌曲的选择，明确提示结果并允许重试。
- 删除统一放在多选工具栏，按钮名称为“删除”；移除逐曲删除图标及歌曲设置中的“移入回收站”入口，不单独提供全歌库删除按钮。批量删除前一次确认并说明影响，沿用当前歌单移除规则：默认歌单独有歌曲进入回收站，其余仅移除当前关系；部分失败时保留失败项选择并提示重试。
- 多选工具栏同时提供“移动到”：将所选歌曲移至其他歌单，目标已包含时只移除来源关系；每首歌的加入目标和移除来源必须原子完成，失败时保留原归属。允许默认歌单参与移动，移动不删除歌曲、不进入回收站，保留其他歌单关系、歌词及播放设置；批量部分失败时仅保留失败项供重试。
- 用户可以从默认歌单移除歌曲；当歌曲只属于默认歌单时，按删除歌曲处理并二次确认。
- 删除普通歌单不得删除其中的歌曲。
- 空歌单不能开始播放，并应给出明确提示。
- 初版不为歌单条目提供独立的权重、播放区间或音量设置。

### 5.7 播放控制

初版只支持两种播放模式：

- 单曲循环
- 歌单内加权随机

客户端至少应提供：

- 播放和暂停
- 加权随机模式下尚未选择歌曲时，点击播放直接从当前歌单按现有加权规则选择一首并开始播放；空歌单禁用播放按钮，单曲循环模式下仍需先选择歌曲。
- 歌曲列表不提供独立播放按钮；点击歌曲行播放，当前歌曲暂停时点击继续，已播放时点击不重置进度。行获得焦点后可按 Enter 播放该曲；空格始终控制当前歌曲的播放 / 暂停，即使焦点在其他歌曲行上也不切歌。勾选和设置操作不触发播放。
- 切换到下一首随机歌曲
- 拖动播放进度
- 调整播放器主音量
- 切换播放模式
- 查看当前歌曲、播放进度和所在歌单

初版不提供传统顺序播放和普通列表循环。

基础快捷键：空格播放 / 暂停，N 下一首，左右方向键后退 / 前进 5 秒，上下方向键调整主音量 5%，M 静音 / 恢复此前音量，? 查看说明。快进快退遵守歌曲播放区间，音量限制在 0–100%；无选中歌曲时空格沿用加权随机的起播规则。文本输入、输入法组合、滑块和弹窗内不触发全局播放快捷键，不拦截浏览器组合键；按钮和链接等已有的空格操作优先；歌曲行不拦截空格，按住切歌或切换键不连续触发。宽屏工具组提供快捷键说明入口，说明支持 Esc 关闭。

### 5.8 单曲播放区间

每首歌曲可以设置只播放其中一段：

- 起点默认为 `0`。
- 终点默认为歌曲结尾；未明确设置终点时，以当前音频自身的结束事件为准，不按元数据时长提前截断。
- 必须满足 `0 <= 起点 < 终点 <= 音频时长`。
- 播放、恢复和拖动进度均不得落在有效区间之外。
- 到达设置的终点时，视为歌曲自然播放结束。
- 单曲循环只循环有效区间。
- 用户可以一键恢复为播放完整歌曲。

播放区间跟随歌曲，对歌曲所在的所有歌单生效。

### 5.9 单曲音量

- 单曲音量跟随歌曲，对所有歌单生效。
- 取值范围为 `0%` 至 `100%`。
- 默认值为 `80%`，为用户上调较安静的歌曲预留空间。
- 播放器主音量默认值为 `100%`。
- 实际音量为播放器主音量与单曲音量的乘积。
- 初版不对音频进行超过原始电平的数字增益。

### 5.10 加权随机播放

#### 5.10.1 基础权重

- 每首歌曲具有用户可编辑的基础权重。
- 默认值为 `1.0`。
- 基础权重必须是大于 `0` 的有限浮点数。
- 权重只影响加权随机模式。

#### 5.10.2 有效权重与恢复

播放器为当前会话中的歌曲计算有效权重，且不得修改用户保存的基础权重。

歌曲被播放后，其有效权重立即降为 `0`。随后每成功切换到一首不同歌曲，恢复一步，按当前歌单可播放歌曲数的一半线性恢复到 100%。奇数数量不取整，例如 5 首歌在切歌 2 次后恢复 80%，第 3 次达到 100%。以 10 首歌的歌单为例：

| 距离上次播放的切歌次数 | 有效权重比例 |
| --- | ---: |
| 0 | 0% |
| 1 | 20% |
| 2 | 40% |
| 3 | 60% |
| 4 | 80% |
| 5 或更多 | 100% |

计算规则为：

```text
有效权重 = 基础权重 × min(1, 距离上次播放的切歌次数 / max(1, 当前歌单可播放歌曲数 / 2))
```

从当前歌单的候选歌曲中，按照有效权重占有效权重总和的比例随机选择下一首。

恢复周期按整个当前歌单的可播放歌曲数计算，不按排除最近歌曲后的候选数计算。歌单增删歌曲后立即按新数量计算比例；未在当前会话播放过的歌曲始终使用完整基础权重。最近两首的硬性避让仍优先于恢复比例。

#### 5.10.3 防止连续重复

- 只要歌单中存在其他可播放歌曲，当前歌曲就不得被选为下一首。
- 随机选择时，只要有其他候选，最近播放的两首都不参与抽取，避免 A → B → A；等待至少两次切歌后才重新成为候选，之后仍按原有效权重抽样。只有两首可播放歌曲时允许交替，不会因避让而停止播放。
- 歌单中只有一首可播放歌曲时，允许再次播放该歌曲。
- 用户手动选择一首歌曲时，也将其视为刚刚播放，并重置该歌曲的衰减状态。
- 手动点歌不受最近两首避让限制；重复点选当前歌曲不推进其他歌曲的恢复步数。
- 单曲循环不会推进其他歌曲的恢复步数。

#### 5.10.4 会话边界

- 切换歌单时创建新的随机会话，并清空之前的随机衰减状态。
- 页面刷新后恢复同一播放会话，不清空衰减状态。
- 如果歌单内容发生变化，应移除已不存在歌曲的状态，并为新加入歌曲使用完整基础权重。

### 5.11 刷新恢复

客户端使用浏览器本地存储保存：

- 数据结构版本
- 当前用户 ID
- 播放会话 ID
- 当前歌单 ID
- 当前歌曲 ID 和音频版本 ID
- 当前播放位置
- 播放模式
- 播放器主音量
- 当前随机衰减状态
- 最后保存时间

保存规则：

- 播放过程中每 2 秒最多保存一次最新进度，避免高频写入；会话按服务器确认的当前用户隔离，并记录会话 ID 和最后实际保存时间。
- 暂停、切歌、切换歌单、手动跳转、播放模式或主音量变化以及页面退出、隐藏时立即保存。
- 页面恢复时验证用户、歌单、歌曲和音频版本仍然有效；恢复和歌单刷新后，清理不属于当前歌单、已删除及格式非法的随机衰减条目。
- 恢复位置超出歌曲播放区间时，将其限制到有效区间内。
- 找不到原歌曲或原歌单时，应放弃对应状态并安全回退，不能阻止页面使用。

本地存储不是服务器数据的替代品；清除浏览器数据只会丢失播放会话，不会删除音乐、歌词或歌单。

- 初版不协调多个浏览器标签页的播放状态。
- 每个标签页可以拥有独立播放会话；多个标签页同时播放或状态不同是允许的。
- 初版优先使用标签页隔离且刷新后仍可恢复的浏览器会话存储，实现上不要求跨标签页同步。

### 5.12 存储空间

- 整套本地服务共享的总空间配额暂定为 10 GiB，即 `10 × 1024³` 字节。
- 配额统计包括原始音频、播放副本、处理中间文件、候选替换版本、封面以及回收站中的文件。
- 数据库文本和运行日志暂不计入用户可见配额。
- 界面不显示“音乐空间 / 你的私人播放站”品牌块。歌单名与曲数仅在歌单导航展示，列表上方不重复显示“当前歌单”、歌单名和曲数；保留上传及普通歌单的重命名、删除入口。“上传音乐”与“添加到 / 移动到 / 删除”位于同一工具栏，不单独占一行，窄屏上传进度入口使用图标以节省空间。回收站与存储空间归为同一工具组，不混入歌单导航；宽屏位于左下角，窄屏在顶部歌单旁以图标显示，回收站保留可访问名称与数量提示。
- 宽屏客户端在左下角统一显示“已用 / 总容量”和容量进度条，不另列剩余空间；窄屏收起为顶部的存储图标，点击展开，点击外部或按 Escape 收起，不常驻遮挡歌词与列表。“上传音乐”保持靠右，上传任务入口临时出现在其左侧，出现、完成或隐藏均不移动上传按钮；窄屏歌词界面或回收站没有上传按钮时，暂时浮动在播放器上方。任务组件切换位置时不卸载，仍继续跟踪任务；没有可展示状态时不占位置。显示占用包含处理中预留，预留数值可通过悬停提示查看。
- 并发上传和转码必须使用原子预留或等效机制计算空间，不能因并发导致总占用突破配额。
- 上传过程中发现剩余空间不足时，应安全终止该文件并清理未完成文件。

### 5.13 默认账号及多账号预留

- 初版启动后自动使用固定的默认用户。
- 界面不显示账号相关功能。
- 歌曲、歌词、歌单等业务数据必须具有明确的用户归属。
- 服务端通过统一的当前用户上下文提供默认用户，业务代码不得散落硬编码默认用户。
- 用户资源访问缺少当前用户上下文时必须失败，不自动采用默认账号；后台任务与恢复按记录所属用户执行。每位用户使用自己的默认歌单，跨用户的歌曲、歌单和任务不能通过猜测 ID 读取、修改或关联；实例总容量仍共享。
- 客户端不得通过任意传入用户 ID 来冒充其他用户。
- 浏览器本地播放状态按用户 ID 隔离。
- 数据结构和服务边界应允许以后加入凭证、登录会话和角色，但初版不实现密码和权限校验。

## 6. 异常与边界情况

- 音频文件缺失、损坏或转码失败时，歌曲应显示不可播放状态并给出原因。
- 随机播放应跳过不可播放或仍在处理中的歌曲。
- 如果歌单中没有可播放歌曲，应停止播放并明确提示。
- 当前歌曲被删除或替换时，客户端应停止旧音频并重新校验会话。
- 服务端重启后，已经持久化的音乐、歌词、歌单和设置不得丢失。
- 页面与服务端失去连接时，应显示连接状态，不能误报为歌曲已删除。
- 音频服务必须支持 HTTP Range 请求，以支持拖动进度和大文件播放。
- 回收站清理失败时应保留可重试状态，不能留下仍计入配额但无法识别的孤立文件。

## 7. 初版不包含

- 密码、注册、真实登录和权限管理
- 多设备同步播放状态
- 服务端或桌面后台持续播放
- 无需用户确认即自动写入歌词
- 逐字歌词和复杂 LRC 扩展
- 在线音乐源
- 歌曲或歌单分享
- 普通顺序播放和列表循环
- 超过原始音频电平的单曲增益
- 以无损保存播放副本为目标的转码
- 面向公网或局域网开放时所需的真实认证、TLS 和反向代理配置；Linux 部署支持需要预留，但这些安全能力不属于当前本机 MVP
- React Native、Android 或 iOS 原生客户端；初版只做网页，但共享业务层不得依赖浏览器专用 API

## 8. 验收场景

### 8.1 上传与默认歌单

上传一个可支持的音频文件后，系统创建歌曲并将其加入默认歌单；刷新页面或重启服务后仍然存在且可播放。

### 8.2 不兼容格式处理

一次选择多个文件，逐个显示上传进度、等待处理、处理中、成功或失败。上传浏览器无法直接播放但服务端可解码的格式后，系统显示处理状态，并在转码成功后允许网页播放。完整接收后刷新网页不影响后台处理，服务重启后能够继续未完成转码；无效文件、空间不足和传输中断保留失败原因并清理候选文件。

### 8.3 加权随机与防重复

在至少包含两首可播放歌曲的歌单中随机播放时，任何一次自动或手动切歌都不会立即再次选择当前歌曲；被播放歌曲的有效权重按切歌次数恢复。

### 8.4 播放片段

为歌曲设置有效起点和终点后，从任何歌单播放该歌曲都只播放该区间；单曲循环也只循环该区间。

### 8.5 刷新恢复

播放中刷新网页后，客户端恢复原歌单、歌曲、接近刷新前的进度、模式、主音量和随机衰减状态。

### 8.6 替换音频

替换歌曲文件成功后，歌曲 ID、歌词、设置和歌单引用保持不变，旧音频版本立即进入清理流程且不再可用；替换失败时旧音频仍可播放。

### 8.7 默认歌单移除

从默认歌单移除一首仍属于其他歌单的歌曲时，只移除默认歌单关系；移除一首只属于默认歌单的歌曲时，客户端二次确认并在确认后将歌曲放入回收站。

### 8.8 回收站清理

删除歌曲后的 72 小时内，任何自动清理触发都不能永久移除文件；满 72 小时后，下一次合适的清理触发可以永久移除歌曲并释放配额。

### 8.9 空间配额

客户端显示 10 GiB 总容量及当前已用容量；当并发上传可能突破配额时，服务器只接受能够成功预留空间的文件。

### 8.10 封面提取与展示

- 上传时提取音频内嵌的第一张封面，已有歌曲在后台补提取；用户可以选择本地图片替换封面。
- 歌曲列表显示小封面，底部播放器显示当前歌曲封面；无封面或加载失败时使用音乐符号占位。
- 歌词区以低透明度封面配合深色遮罩作为背景，歌词保持清晰且能够正常点击、滚动；没有歌词时也显示封面背景。
- 缺少、损坏的内嵌封面或封面空间不足不阻止有效音频上传。封面计入容量，跟随歌曲进入回收站、恢复与到期清理；替换音频成功后使用新文件封面并立即清理旧封面，新文件没有封面则恢复占位。

- 歌曲设置中“替换封面”和“替换音频”使用统一样式的按钮，同一行显示，点击直接选择文件。选择封面图片后直接在原封面缩略图的位置预览，不单独占一行；选择替换音频后显示文件名。两者都只暂存于当前设置窗口，由底部“保存”统一提交，取消设置丢弃未提交的选择，不上传文件。保存期间禁用重复提交和编辑，全部完成后关闭；失败保留未完成的选择供重试，并明确告知已完成的部分不会撤销。支持 JPG、PNG、WebP、GIF、BMP，单图不超过 8 MiB；动图采用第一帧。
- 不再提供在线封面搜索、候选列表或网络图片下载。已保存的在线封面继续可用。
- 封面保存由可恢复后台任务执行，成功后更新列表、歌词背景和播放器，保持音频版本与播放进度；失败保留旧封面并显示原因，允许重试。上传的临时图片与派生 JPEG 均占用配额，成功后清理临时文件和旧封面。完整接收后刷新或重启服务仍可继续处理。
